# Инструкция: генерация вопроса из раздела документации

Ты получаешь список разделов официальной документации. Для каждого раздела подготовь ровно один вопрос квиза.

Вход — JSON-файл батча, поле `sections` (id, topic, title, url, grade). Выход — строго JSON без markdown-обёртки:

```json
{
  "batchId": "<batchId из входа>",
  "results": [
    {
      "sectionId": "<id раздела>",
      "topic": "<topic из раздела>",
      "grade": "junior | middle | senior",
      "question": "<формулировка вопроса на русском>",
      "answer": "<правильный ответ, 1–3 предложения>",
      "options": ["<вариант>", "<вариант>", "<вариант>", "<вариант>"],
      "correctIndex": 0,
      "explanation": "<общее пояснение к вопросу, 1–3 предложения>",
      "docsRefs": ["<ссылка на официальную документацию>"]
    }
  ],
  "skipped": [{ "sectionId": "<id>", "reason": "<почему раздел не подошёл>" }]
}
```

## Правила

1. Открой `url` раздела и составь вопрос по его содержанию; `docsRefs` обязан включать URL раздела, можно добавить смежные официальные страницы.
2. Один раздел — один вопрос. Вопрос проверяет понимание, а не заучивание перечисления.
3. 4 различных варианта, ровно один верный; дистракторы правдоподобные, но однозначно неверные.
4. `grade` — обычно `grade` раздела; допустимо на шаг выше (junior → middle, middle → senior), если вопрос проверяет механику, компромисс или оптимизацию. На шаг ниже нельзя.
5. `topic` — строго из раздела.
6. Всё на русском языке, технические термины можно латиницей.
7. Раздел устаревший, экспериментальный или слишком узкий для вопроса — добавь в `skipped` с причиной.
