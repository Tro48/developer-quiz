# Инструкция: генерация вариантов ответа

Ты обрабатываешь батч вопросов квиза по фронтенд-разработке.
Вход — JSON-файл батча, поле `questions`. Выход — строго JSON без markdown-обёртки.
Не создавай никаких других файлов, верни только JSON-текст.

## Схема выхода

```json
{
  "batchId": "<batchId из входа>",
  "results": [
    {
      "id": "<id вопроса>",
      "grade": "junior | middle | senior",
      "answer": "<правильный ответ, 1–3 предложения>",
      "options": ["<вариант>", "<вариант>", "<вариант>", "<вариант>"],
      "correctIndex": 0,
      "explanation": "<общее пояснение к вопросу, 1–3 предложения>",
      "docsRefs": ["<ссылка на официальную документацию>"]
    }
  ],
  "skipped": [{ "id": "<id вопроса>", "reason": "<почему не удалось подтвердить>" }]
}
```

## Правила

1. Для каждого вопроса найди официальную документацию: MDN (JavaScript, HTML, CSS, DOM), react.dev, TypeScript Handbook, web.dev, официальные доки библиотек (Redux, Zustand и т. п.). Используй веб-поиск и загрузку страниц.
2. `docsRefs` — минимум одна рабочая ссылка на конкретную страницу документации, по которой проверен ответ. Статьи, блоги, подборки вопросов и видео не подходят.
3. Если в вопросе есть готовый ответ из источника — сверь его с документацией; при расхождении верь документации.
4. Если ответа нет — сформулируй сам и подтверди документацией.
5. `options` — 4 различных варианта, ровно один верный (`correctIndex`), остальные правдоподобные, но однозначно неверные. Запрещены варианты «все перечисленное», «оба ответа верны», «ничего из перечисленного».
6. Если у вопроса `source = yauhenkavalchuk` (в источнике нет ответов и лицензия не указана) — переформулируй текст вопроса своими словами, сохранив смысл. Вопросы Hexlet переписывать не нужно.
7. `explanation` — почему верный вариант верен, без воды и без пересказа вопроса.
8. `grade` — оцени сложность для фронтенд-собеседования: `junior`, `middle` или `senior`.
9. Всё на русском языке, технические термины можно латиницей.
10. Если ответ не подтверждается документацией — не выдумывай: добавь вопрос в `skipped` с причиной.
