# developer-quiz

Требования и решения.

## Что это

Мобильное приложение для Android на React Native — интерактивный квиз по фронтенд-разработке.
Вопросы идут с вариантами ответов, пользователь проходит их по одному.

## Приложение и релизы

Android-сборки публикуются в [GitHub Releases](https://github.com/Tro48/developer-quiz/releases):
APK ставится поверх установленного приложения, версия и `versionCode`
поднимаются автоматически. Изменения JavaScript и банка вопросов
доставляются по воздуху (EAS Update); APK собирается только при изменении
нативной части.

Выкатка: пуш в `main` → проверки → версия → развилка по отпечатку нативной
части. Ручная сборка APK — workflow `Сборка Android`.

Обновление банка вопросов:

```bash
npm run build
cd app && npm run db:copy
git add app/assets/db/questions-v2.db data/bank/questions.json
git commit -m "Банк вопросов: <что изменилось>"
```

## Организация вопросов

- Весь банк вопросов разделён на группы по грейду разработчика.
- Каждому грейду соответствует собственный набор вопросов, максимально подходящий этому уровню.
- Один квиз — случайная порция из 15–20 вопросов из текущего пула грейда.
- Вопросы размечены по темам (технологиям): JavaScript, TypeScript, React, HTML, CSS и другие.
- Темы выбираются в настройках и действуют на все квизы: в квиз попадают только вопросы выбранных тем.

## Модель прогресса: тема × грейд

- Прогресс хранится по паре «тема × грейд».
- Грейд темы закрывается, когда верно отвечены все вопросы этой темы в этом грейде.
- Следующий грейд темы открывается после закрытия предыдущего.
- Грейд считается пройденным, когда закрыты все выбранные темы в этом грейде; после этого открывается следующий грейд.
- Добавление новой темы посреди прохождения: её младшие грейды нужно закрыть, чтобы догнать текущий. Пока это не сделано, прогресс текущего грейда приостановлен.
  - Пример: пользователь на Middle добавляет Zustand — сначала закрывает Junior по Zustand, только потом возобновляет Middle.
- Отключённая тема не попадает в квизы и не учитывается в прогрессе; при повторном включении прогресс темы сохраняется.
- При добавлении темы закрываются все её предыдущие грейды (на Senior — Junior и Middle).

## Механика прохождения

- Квиз считается пройденным, когда даны ответы на всю порцию вопросов.
- После выбора варианта сразу видно, верный он или нет, и показывается пояснение.
- Если вопрос отвечен неверно, он остаётся в пуле и попадает в следующие квизы этого грейда в случайном порядке.
- Верно отвеченный вопрос выпадает из ротации сразу и в следующих квизах не участвует.
- Грейд не закрывается до тех пор, пока не будут даны правильные ответы на все вопросы его банка.
- Пока текущий грейд не закрыт, следующие грейды недоступны.
- Грейды открываются последовательно, по мере прохождения.
- Если в пуле меньше 15 вопросов, в квиз берутся все оставшиеся.

## Экран результатов и прогресс

- По завершении квиза — экран «квиз завершён» с результатом.
- Для каждого грейда отображается прогрессбар: сколько вопросов закрыто из общего числа.

## Решённые вопросы

- ✅ Источник вопросов — открытые репозитории и статьи, список утверждён (см. «Источники»).
- ✅ Язык вопросов — русский.
- ✅ Верно отвеченный вопрос выпадает из ротации сразу.
- ✅ Размер квиза — случайные 15–20 вопросов из текущего пула грейда.
- ✅ Формат ответов — 4 варианта, один верный.
- ✅ Хранение прогресса — только на устройстве, без аккаунта и сервера.
- ✅ Таймер и жизни не нужны — прохождение без ограничений по времени.
- ✅ Обратная связь сразу после выбора варианта: подсветка верного/неверного и пояснение.
- ✅ По завершении квиза — экран с результатом и прогрессбары по грейдам.
- ✅ Выбор тем — постоянная настройка в приложении, действует на все квизы.
- ✅ Закрытие грейда считается по выбранным темам; добавление новой темы требует сначала закрыть её младшие грейды.
- ✅ Пояснение к вопросу общее: после выбора подсвечивается верный/неверный вариант и показывается один поясняющий текст.
- ✅ Банк вопросов и прогресс — в локальной базе данных на устройстве (SQLite); конкретная библиотека — на этапе выбора стека.
- ✅ Варианты ответов: агент генерирует верный ответ (там, где его нет), 3 дистрактора и пояснение, затем автоматическая сверка с официальной документацией; ручной вычитки нет.
- ✅ Пайплайн подготовки банка утверждён.
- ✅ Hexlet берём дословно; приложение будет с открытым исходным кодом под AGPL-3.0.
- ✅ Прогресс темы сохраняется при отключении и повторном включении.
- ✅ Новый квиз можно запускать сразу после завершения предыдущего, без ограничений.
- ✅ Грейды — junior / middle / senior; целевой размер банка (686 вопросов по пяти технологиям) и метод разбивки по грейдам утверждены.
- ✅ Каноническая таксономия утверждена: ядро из пяти тем, резерв со статусом «позже».
- ✅ Режим генерации из разделов документации внедрён (docgen) и применён в пилоте: 29 verified из MDN; смешанная секция Hexlet разделена topicfix.

## Открытые вопросы

- ❓ Сборка базы: JavaScript 260/260 и CSS 88/80 — цели достигнуты; TypeScript 50/66, React 105/130, HTML 79/150. Остаток (+112) закрывается docgen-картами TypeScript, React и HTML; в docmap нужен host-allowlist (TS и React — не MDN).
- ❓ Переформулировка вопросов из источников без лицензии: схема вывода генерации не содержит текст вопроса, поэтому переформулировка не сохраняется. Решить до публикации.
- ❓ `npm run report` до первого merge показывает ноль, потому что читает только рабочую базу `data/generated/questions.json`; в runbook обещано иначе.

Следствия для работы:

- Готовых вариантов ответов нет ни в одном источнике — к каждому вопросу нужно готовить 3 неверных варианта.
- У YauhenKavalchuk нет текстовых ответов: правильные ответы будут сгенерированы и сверены с официальной документацией.
- Разбивка по грейдам на уровне вопросов есть только у Hexlet; в остальных источниках её нет, классифицировать придётся самим.
- Лицензии у большинства не указаны, у Hexlet — AGPL-3.0. Решение: Hexlet используем дословно, приложение будет открытым под AGPL-3.0. Для источников без лицензии дословное копирование всё равно юридически серо — при генерации такие вопросы надёжнее переформулировать.
- Статьи (Habr, Proglib и подобные) тоже подходят, но парсить их сложнее: нет единого формата, много разметки и рекламы.
